# AutoParts — Vehicle-First Parts Catalog (MVP)

A working scaffold implementing the documented spec: FastAPI backend + Next.js frontend, header
vehicle selector (VIN/reg or Make/Model/Generation/Engine), 3-level catalog (System → Subsystem,
with Part Type as a sidebar filter), product detail pages with fitment confirmation, search, and
a My Garage page.

## Running the backend

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
API docs (auto-generated by FastAPI) will be at http://localhost:8000/docs

Data is currently **in-memory, seeded on startup** from `backend/app/data.py` — a handful of
categories, brands, parts, fitments, and demo vehicles (VW Golf Mk7, Toyota Corolla, Ford Focus).
This is deliberately storage-agnostic: every route calls functions in `data.py`
(`category_children`, `parts_in_category`, `part_fits_vehicle`, etc.) rather than touching data
structures directly, so swapping in real MongoDB (via `motor`) later means rewriting `data.py`
only — routers don't change.

## Running the frontend

```bash
cd frontend
npm install
npm run dev
```
Opens at http://localhost:3000. It expects the backend at `http://localhost:8000` by default
(override with `NEXT_PUBLIC_API_BASE` in a `.env.local` file).

## What's implemented
- Header: logo, search bar, persistent vehicle selector ("My Garage"), catalog link
- Vehicle selector: VIN/reg tab (stub decoder — swap for a real VIN API) + Make → Model →
  Generation → Engine cascading selector tab
- Homepage: hero with vehicle selector + category grid (Car Parts / Accessories roots)
- Catalog: `/catalog` (all systems) → `/catalog/[system]` (subsystems) →
  `/catalog/[system]/[subsystem]` (product grid + Part Type/Brand sidebar filters + "fits my
  vehicle" toggle) — matching the 3-page-level / filter-facet pattern found on Trodo.com
- Product detail page: specs tab, "Fits These Vehicles" tab, description tab, fitment
  confirmation banner
- Search page (`/search?q=...`), vehicle-aware if a vehicle is active
- My Garage page (saved vehicles, switch active vehicle)
- Active vehicle persists via `localStorage` across the whole session

## What's NOT implemented yet (next steps)
- Real VIN decode integration (currently a deterministic stub in
  `backend/app/routers/vehicles.py::decode_vin` — swap for NHTSA API or a licensed TecDoc provider)
- Real reg-number lookup (market-dependent; not wired up)
- MongoDB persistence (currently in-memory — resets on backend restart)
- Cart / checkout / payment
- User accounts / auth (Garage is currently a single shared in-memory list, not per-user)
- Product images (placeholders only)
- Full taxonomy — only a representative subset of categories/parts is seeded; extend
  `backend/app/data.py` following the same pattern to add the rest of the documented taxonomy
- Meilisearch/Typesense (search currently does a simple in-memory substring match — fine for
  small catalogs, won't scale to a large one)

## Extending the catalog
To add more categories, brands, parts, or vehicles, edit `backend/app/data.py` — it's a single
readable file with helper functions (`_add_category`, `_add_brand`, `_add_part`, `_add_fitment`,
`_add_vehicle`). Follow the existing pattern; no other file needs to change for new data.
