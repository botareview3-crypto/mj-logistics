# Setting up Google & Apple Sign-In

The code is wired up and ready (`backend/app/routers/auth.py`,
`frontend/lib/auth.ts`, the buttons on `/account`). It won't work until you
supply real credentials — here's exactly what to do, in order.

## 0. The moving pieces
- **Database**: accounts are stored in Postgres (`mj-logistics-db` in
  `render.yaml`) via SQLAlchemy. Render creates this automatically when you
  redeploy from the updated `render.yaml` — no action needed from you here.
- **JWT_SECRET / SESSION_SECRET**: auto-generated by Render, no action needed.
- **Google & Apple credentials**: these you have to create yourself — no one
  else can, since they're tied to your accounts/domain.

## 1. Google (~10 minutes, free)
1. Go to the [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
2. Create a project (or pick an existing one).
3. Configure the **OAuth consent screen** (External, add your app name + your
   email as support contact — no verification needed for basic sign-in).
4. Create **Credentials → OAuth client ID → Web application**.
5. Under **Authorized redirect URIs**, add:
   ```
   https://mj-logistics-backend-7crs.onrender.com/api/auth/google/callback
   ```
   (swap in your real backend URL if it's different — check the Render
   dashboard for `mj-logistics-backend`'s URL).
6. Copy the **Client ID** and **Client Secret**.
7. In the Render dashboard → `mj-logistics-backend` → Environment, set:
   - `GOOGLE_CLIENT_ID`
   - `GOOGLE_CLIENT_SECRET`

That's it — Google will work as soon as you redeploy.

## 2. Apple ($99/year Apple Developer Program membership required)
Apple's setup is more involved and the membership isn't free.
1. Enroll at [developer.apple.com](https://developer.apple.com/programs/) if
   you haven't already.
2. **Certificates, Identifiers & Profiles → Identifiers → App IDs**: make
   sure you have one, with "Sign in with Apple" capability enabled.
3. **Identifiers → Services IDs**: create one (this is your `APPLE_CLIENT_ID`
   — it looks like `com.yourcompany.web`, not your app's bundle ID). Enable
   "Sign in with Apple" on it, and configure:
   - **Domains**: your backend's domain, e.g. `mj-logistics-backend-7crs.onrender.com`
   - **Return URLs**: `https://mj-logistics-backend-7crs.onrender.com/api/auth/apple/callback`
4. **Keys**: create a new key with "Sign in with Apple" enabled, download the
   `.p8` file (you can only download it once — save it somewhere safe). Note
   the **Key ID** shown on the key's page.
5. Find your **Team ID** (top-right of the Apple Developer account page).
6. In Render → `mj-logistics-backend` → Environment, set:
   - `APPLE_CLIENT_ID` = the Services ID (e.g. `com.yourcompany.web`)
   - `APPLE_TEAM_ID`
   - `APPLE_KEY_ID`
   - `APPLE_PRIVATE_KEY` = the full contents of the `.p8` file, with actual
     newlines replaced by `\n` (Render's env var editor is single-line) —
     e.g. `-----BEGIN PRIVATE KEY-----\nMIGT...\n-----END PRIVATE KEY-----\n`

**Heads up:** Apple does not allow `localhost` redirect URIs, so Apple
sign-in can only be tested against the real deployed backend, not your local
machine.

## 3. Redeploy
Push these files and redeploy on Render (or "Sync" the Blueprint if you're
using render.yaml directly). Once GOOGLE_CLIENT_ID/SECRET are set, Google
sign-in works immediately; Apple works once its four vars are set.

## 4. When the frontend moves to Hostinger
`FRONTEND_URL` (the address a user is redirected back to after signing in)
currently points at the temporary Render static site. When you move the
storefront to Hostinger per `HOSTINGER-DEPLOY.md`:
- Update `FRONTEND_URL` in Render to your Hostinger domain.
- Add that domain to Google's "Authorized JavaScript origins" (Credentials
  page) and to Apple's Services ID **Domains** list.
- The backend callback URLs themselves don't change (they still point at
  Render), only where the user lands afterward.

## Testing without real accounts yet
Until credentials are set, clicking "Continue with Google/Apple" will hit
the backend and fail gracefully (`auth_error` toast) rather than crash — so
it's safe to deploy this now and add credentials whenever you're ready.
